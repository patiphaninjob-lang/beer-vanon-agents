# คัมภีร์การอัปเกรดระบบและฟีเจอร์แอปพลิเคชันหุ้นไทย (Thai Stock App Parity Roadmap)

*เอกสารฉบับนี้จัดทำขึ้นเพื่อบันทึกรายละเอียดและโครงสร้างทางสถาปัตยกรรม (Architectural Blueprint) ของการอัปเกรดระบบและฟีเจอร์ในฝั่งแอปหุ้นสหรัฐฯ (US Stock App) ไว้อย่างละเอียดที่สุด เพื่อใช้เป็นแนวทางให้ AI ในอนาคตสามารถพอร์ตฟีเจอร์และแก้ไขแอปหุ้นไทยได้อย่างราบรื่นและไร้รอยต่อ*

---

## 📅 บันทึกประวัติและรายละเอียดฟีเจอร์ที่อัปเกรดในฝั่ง US (Detailed US Version History)

### 📌 ฟีเจอร์ที่ 1: ระบบแยกข้อมูลประวัติราคาและกราฟรายดัชนีตลาด (Separated Market History & Charts)
*   **แนวคิดดั้งเดิม**: ประวัติกราฟตลาดรวมจะใช้ไฟล์เดียวกันโดยเน้นดัชนี Dow Jones ส่งผลให้ทุกดัชนีหน้าตาเหมือนกันและอัปเดตไม่สมบูรณ์
*   **สิ่งที่พัฒนาใน US**:
    1.  **ฝั่งบอทวิเคราะห์ (`beer_top100_agent.py`)**:
        - เพิ่มระบบดึงราคาดัชนีหลักจาก `yfinance` แยกตามรหัสสากล: `^DJI` (Dow Jones), `^GSPC` (S&P 500), `^IXIC` (NASDAQ)
        - ดึงประวัติราคาย้อนหลังด้วย Period = `5y` และ Interval = `1d` จากนั้นนำมาประมวลผลแยกและบันทึกเป็นไฟล์ JSON อิสระลงในโฟลเดอร์ `docs/history-data/` โดยตั้งชื่อว่า:
          - `_DJI.json`
          - `_SPX.json`
          - `_IXIC.json`
        - คีย์ดัชนีจะถูกเขียนนำหน้าด้วยเครื่องหมายขีดล่าง `_` เพื่อแยกออกจากหุ้นรายตัวปกติ
    2.  **ฝั่งหน้าเว็บประวัติ (`docs/history.html`)**:
        - แก้ไขฟังก์ชันรับค่าพารามิเตอร์ `ticker` จาก Query String ของ URL (เช่น `history.html?ticker=_SPX&date=2026-06-27`)
        - เมื่อรับค่าพารามิเตอร์นำหน้าด้วย `_` ระบบจะสลับไปดึงข้อมูลจาก `history-data/_SPX.json` (แทนที่จะดึงประวัติหุ้นปกติ) และวาดเส้นกราฟดัชนีตลาดนั้นๆ ได้อย่างถูกต้อง
    3.  **ฝั่งหน้าเว็บหลัก (`docs/index.html`)**:
        - อัปเดตลิงก์ในปุ่มประวัติราคาของการ์ดภาพรวมตลาดแต่ละใบให้เรียกใช้ `openMarketHistory('_DJI')`, `openMarketHistory('_SPX')`, หรือ `openMarketHistory('_IXIC')`
*   **รายละเอียดสถาปัตยกรรมสำหรับหุ้นไทย**:
    - ต้องปรับบอทหุ้นไทย (`thai_top100_agent.py`) ให้ดึงข้อมูลดัชนีไทย เช่น **SET Index** (`^SET.BK`) และ **SET50 Index** (หรือดัชนีอ้างอิงอื่นๆ)
    - บันทึกเป็นไฟล์ `_SET.json` และ `_SET50.json` ลงในโฟลเดอร์ `docs/thai-history-data/`
    - หน้าเว็บประวัติของไทยต้องดึงไฟล์เหล่านี้ตามพารามิเตอร์ `ticker=_SET` หรือ `_SET50`

### 📌 ฟีเจอร์ที่ 2: ระบบแยกบันทึกมุมมอง/โน้ตอารมณ์ตลาดตามดัชนี (Separated Market Sentiment Notes)
*   **แนวคิดดั้งเดิม**: เมื่อผู้ใช้กดปุ่มบันทึกมุมมองตลาด โน้ตทั้งหมดจะบันทึกรวมกันอยู่ใต้คีย์เดียว ทำให้ทุกดัชนีมีโน้ตทับซ้อนกัน
*   **สิ่งที่พัฒนาใน US**:
    1.  **การแยกคีย์โน้ต (Database Keys)**:
        - กำหนดคีย์สำหรับบันทึกโน้ตในไฟล์ `notes.json` แยกตามประเภทดัชนี ได้แก่:
          - `_MARKET` (โน้ตรวมของตลาดทั่วไป)
          - `_DJI` (โน้ตเฉพาะดัชนี Dow Jones)
          - `_SPX` (โน้ตเฉพาะดัชนี S&P 500)
          - `_IXIC` (โน้ตเฉพาะดัชนี NASDAQ)
    2.  **ฝั่งโมดอลจดโน้ต (`docs/index.html`)**:
        - ปรับปรุงฟังก์ชัน `openMarketNote(ticker)` ให้ส่งรหัสตลาดที่เลือก
        - ฟังก์ชันจะแมปป้ายชื่อดัชนีในโมดอลอย่างเหมาะสม: `_MARKET` -> 'ภาพรวมตลาด', `_DJI` -> 'Dow Jones', `_SPX` -> 'S&P 500', `_IXIC` -> 'NASDAQ'
        - เมื่อพิมพ์บันทึกและยืนยัน ข้อมูลจะถูกจัดเก็บลงอาร์เรย์ `notesCache[activeNoteTicker]` และเรียกใช้ระบบเขียนไฟล์ `notes.json` ส่งคืนไปยัง GitHub หรือฐานข้อมูล Cloud
    3.  **การเรนเดอร์ปุ่มบนการ์ดดัชนี**:
        - หน้าเว็บหลักจะนับความยาวของอาร์เรย์โน้ตแต่ละคีย์แบบเรียลไทม์ เช่น `(notesCache['_SPX'] || []).length`
        - เรนเดอร์ข้อความบนปุ่มเป็น `📝 [จำนวน] มุมมอง` (เช่น `📝 2 มุมมอง`) หากมีโน้ตบันทึกอยู่แล้ว หรือเรนเดอร์ `📝 เพิ่มมุมมอง` หากยังไม่มีข้อมูล
*   **รายละเอียดสถาปัตยกรรมสำหรับหุ้นไทย**:
    - แยกคีย์จดโน้ตเป็น `_SET` และ `_SET50` ในไฟล์ `notes.json` ของฝั่งไทย
    - ผูกปุ่มการจดบันทึกให้ทำงานส่งค่าพารามิเตอร์ตามคีย์ดังกล่าว

### 📌 ฟีเจอร์ที่ 3: ระบบสรุปข่าวสารและปัจจัยขับเคลื่อนตลาด (Market Driver Summary) [v2.3.0]
*   **แนวคิดดั้งเดิม**: ไม่มีพื้นที่รวบรวมข่าวสารเศรษฐกิจระดับมหภาคที่มีผลกระทบกระเทือนต่อจิตวิทยาการลงทุนโดยตรง
*   **สิ่งที่พัฒนาใน US**:
    1.  **ฝั่งบอทวิเคราะห์ (`beer_top100_agent.py`)**:
        - สร้างฟังก์ชัน `fetch_and_summarize_market_news()`
        - ดึงข้อมูลข่าวสาร 5 ข่าวล่าสุดผ่าน `yfinance` จากกลุ่มหลักทรัพย์อ้างอิง: `SPY`, `QQQ`, `DIA`, `USO` (น้ำมันดิบ), `GLD` (ทองคำ)
        - ใช้ระบบคัดกรองข่าวมูลค่าซ้ำ (Deduplication) โดยตรวจสอบจาก URL หรือชื่อหัวข้อข่าว และตัดข่าวให้เหลือสูงสุด 12 ข่าวที่สำคัญที่สุด
        - จัดทำข้อมูลข้อความดิบ (Text Block) ส่งต่อไปยัง **Groq API** โมเดล `llama3-70b-8192` (หรือรุ่นอัปเดต)
        - ใช้ Prompt ภาษาไทยสั่งการให้จัดทำข้อความสรุปปัจจัยและอารมณ์ตลาดเป็นประเด็นย่อยในฟอร์แมต JSON:
          ```json
          {
            "summary_bullets": [
              "ข้อสรุปข่าวประเด็นที่ 1...",
              "ข้อสรุปข่าวประเด็นที่ 2..."
            ]
          }
          ```
        - ฟังก์ชันจะคืนค่าเป็นก้อนข้อมูลและนำมาฝังลงในตัวแปร payload ภายใต้ฟิลด์ `"market_news"` ของไฟล์ข้อมูลรายวัน (JSON Archive) ทั้งในรอบ premarket, postmarket และรอบปกติ
    2.  **ฝั่งหน้าเว็บหลัก (`docs/index.html`)**:
        - เพิ่มบล็อก HTML ปลายทาง: `<div id="marketNewsSummary" class="market-news-summary-section" style="display:none"></div>` แทรกไว้ใต้แถวการ์ดดัชนี
        - พัฒนาฟังก์ชัน JavaScript `renderMarketNewsSummary()` เพื่ออ่านข้อมูลจาก `currentData.market_news.summary_bullets` มาสร้างเป็นรายการการ์ดข่าวสรุปประเด็นย่อยอย่างสวยงาม โดยใช้คลาส CSS ตกแต่งที่มีฟีเจอร์ Hover animation เลื่อนไปทางขวาเล็กน้อยเมื่อเอาเมาส์ชี้
        - เรียกฟังก์ชันนี้ในขั้นตอนสุดท้ายของ `loadDate()`
*   **รายละเอียดสถาปัตยกรรมสำหรับหุ้นไทย**:
    - ปรับบอทไทยดึงข่าวจาก ETF ไทย เช่น `TDEX.BK` (อ้างอิงดัชนี SET50) หรือข่าวเศรษฐกิจระดับชาติ
    - สรุปผลกระทบด้านนโยบายการเงิน, นโยบายรัฐบาลไทย, ดอกเบี้ยนโยบายของ ธปท., หรือการส่งออกไทย

### 📌 ฟีเจอร์ที่ 4: การเชื่อมโยงข้อมูล History ↔ Journal และมุดแยกสีอารมณ์แบบ Real-time [v2.4.0]
*   **แนวคิดดั้งเดิม**: หน้าประวัติ (History) และหน้าบันทึกส่วนตัว (Journal) แยกส่วนกันแสดงผล หน้า Journal แสดงเพียงรูปกราฟนิ่ง (.jpg) ไม่สามารถกดดูจุดประวัติแนวคิดการเทรดได้
*   **สิ่งที่พัฒนาใน US**:
    1.  **การปรับปรุงหน้า Journal (`docs/journal.html`)**:
        - เปลี่ยนกล่องภาพกราฟนิ่ง `#chartBox` ให้เป็นกราฟ Interactive ด้วย `<canvas>` แท่งเทียนราคาจริง (Candlestick Chart) แบบเดียวกับหน้าประวัติ
        - เชื่อมโยงดึงข้อมูลประวัติราคาหลักทรัพย์จากโฟลเดอร์ `history-data/` และดึงข้อมูลโน้ต/Journal ของ ticker นั้นๆ จาก Firestore
        - วาดมุด (Markers) บนตำแหน่งแท่งเทียนราคาประวัติของวันที่มีบันทึก (แสดงทั้งโน้ตธรรมดาและบันทึก Journal)
        - เมื่อนำเมาส์คลิกที่จุดมุด ระบบจะแสดง Tooltip รายละเอียดการบันทึกของวันนั้นๆ (แสดงอารมณ์, ความตั้งใจ, ความมั่นใจ, และ Thesis ที่จดไว้ พร้อมการดึงบทวิเคราะห์ของ Beer อัตโนมัติจาก Archive รายวัน)
    2.  **มุดแบบแยกสีตามอารมณ์จิตวิทยา (Emotion-Coded Markers)**:
        - ทำการแยกแยะชนิดของบันทึกโดยวิเคราะห์อารมณ์ (Emotion) ในฟิลด์ `journal.emotion` และแสดงสีจุดบนกราฟ ดังนี้:
          - 🔴 **สีแดง**: อารมณ์ `กลัว`
          - 🟢 **สีเขียว**: อารมณ์ `มั่นใจแต่ระวัง`
          - 🟡 **สีเหลือง**: อารมณ์ `ลังเล`, `ใจเย็นรอ`, `ไม่เชื่อข่าว`
          - 🔵 **สีน้ำเงิน**: อารมณ์ `โลภ`, `FOMO`
          - ⚪ **สีทอง**: โน้ตธรรมดา (ไม่มีข้อมูล Journal)
        - ระบบนี้ทำงานตรงกันทั้งในกราฟของหน้าประวัติ (History) และหน้าเขียนบันทึก (Journal)
    3.  **การอัปเดตการแสดงผลแบบทันที (Real-time Update)**:
        - เมื่อเทรดเดอร์บันทึกมุมมองใหม่ลงบน Cloud สำเร็จ ในฟังก์ชัน `addPreviewEntry()` จะทำการเคลียร์แคชข้อมูลประวัติและดาวน์โหลดเพื่อประมวลผลวาดมุดใหม่แสดงผลทันทีบนหน้าจอกราฟโดยที่เทรดเดอร์ไม่ต้องรีเฟรชเบราว์เซอร์
    4.  **ลิงก์สองทิศทาง**:
        - ในป๊อปอัปรายละเอียดของหน้าประวัติ (History) จะมีปุ่ม `"เปิดใน Journal →"` เพื่อช่วยให้เทรดเดอร์เปิดดูหรือปรับแต่งแผนการเทรดของวันนั้นๆ ได้อย่างรวดเร็ว
*   **รายละเอียดสถาปัตยกรรมสำหรับหุ้นไทย**:
    - หน้า Journal ของไทย (`docs/thai/journal.html` หรือเทียบเท่า) ต้องเปลี่ยนเป็นกราฟเทียน Canvas และเชื่อมโยง notes ของฝั่งไทย
    - ใช้ชุดคำสั่งประมวลผลและการแยกสีมุดตามอารมณ์เช่นเดียวกัน

### 📌 ฟีเจอร์ที่ 5: กราฟแท่งเทียน 3D เรืองแสงแยกตามอารมณ์ และป๊อปอัปสปริงเบลอกระจกสไตล์ iOS [v2.5.0]
*   **แนวคิดดั้งเดิม**: หน้ากราฟจะวาดแท่งเทียนเป็นสีเหลี่ยม 2D แบน ๆ และมีปุ่มวงกลมสีทอง/สีต่าง ๆ ลอยทับอยู่ด้านบน การโต้ตอบผ่านเมาส์จะแข็งทึบและเด้งป๊อปอัปขึ้นมาทันที
*   **สิ่งที่พัฒนาใน US**:
    1.  **กราฟแท่งเทียนแบบ 3D ไล่เฉดกระบอกสูบ (Cylindrical 3D Candlestick)**:
        - เมื่อวิเคราะห์ว่าแท่งเทียนของวันนั้นมีบันทึก (โน้ต หรือ Journal) ระบบจะแปลงรูปร่างแท่งเทียนสี่เหลี่ยมแบนให้ใช้ `createLinearGradient` ไล่เฉดสีจากมืดไปสว่างตรงกลางและขอบมืด ทำให้มีมิติทรงกระบอกกลมนูนสามมิติอย่างชัดเจน
    2.  **ขอบเรืองแสงสะท้อนอารมณ์จิตวิทยา (Neon Glow Outline)**:
        - ยกเลิกการวาดวงกลมมุดลอยเดี่ยวแบบเดิมทั้งหมด และใช้วิธีวาดขอบเรืองแสงนีออนรอบตัวแท่งเทียน 3D ตามสีของอารมณ์ในฟิลด์ Journal (🔴 แดง = กลัว, 🟢 เขียว = มั่นใจแต่ระวัง, 🟡 เหลือง = ลังเล/ใจเย็นรอ/ไม่เชื่อข่าว, 🔵 น้ำเงิน = โลภ/FOMO, ⚪ ขาวทอง = โน้ตทั่วไป)
    3.  **แอนิเมชันความนูนค่อย ๆ พองโต้ตอบ (Fluid Easing Loop via requestAnimationFrame)**:
        - เพิ่มตัวแปร `state.hoveredKey`, `state.hoverIntensities` และฟังก์ชัน `startAnimation()` / `animationLoop()`
        - เมื่อผู้ใช้นำเมาส์เคลื่อนเข้าไปจ่อ (Hover) แท่งเทียน 3D นั้น ตัวแท่งเทียนจะค่อย ๆ พองอวบตัวหนาขึ้น (จากความหนาปกติเพิ่มขึ้นอีก 4px) และเงาเรืองแสงนีออนจะค่อย ๆ สว่างวาบขึ้นมาอย่างนุ่มนวล โดยคำนวณผ่านสมการ Easing `current + (target - current) * 0.18` และจะค่อย ๆ หดตัวคืนสภาพเดิมอย่างสมูทเมื่อเมาส์เลื่อนออก
    4.  **ป๊อปอัป Glassmorphism และความสปริง iOS (Springy Backdrop-Blur Tooltip)**:
        - ปรับปรุง CSS ของ `.marker-tooltip` ให้พื้นหลังลอยด้วย `backdrop-filter: blur(12px)` ผสมสีมืดโปร่งแสง พร้อมตั้งค่าแอนิเมชันการเปิดตัวแบบเด้งนุ่มนวลด้วยเส้นโค้งสปริง `cubic-bezier(0.34, 1.56, 0.64, 1)` สไลด์ลอยเด้งขึ้นมาเมื่อเรียกใช้งาน
*   **รายละเอียดสถาปัตยกรรมสำหรับหุ้นไทย**:
    - นำเข้าชุดลอจิก Easing Loop และ `requestAnimationFrame` เข้าสู่หน้าจอ `history.html` และ `journal.html` ของไทย
    - แก้ไข CSS ทรานซิชันของป๊อปอัปให้แสดงผลสปริงนุ่มนวลเช่นกัน

## 🛠️ รายละเอียดปัญหาทางเทคนิคและการแก้ไข (Detailed Tech Issues & Solutions)

เพื่อป้องกันการเกิดปัญหาซ้ำเดิมเมื่อทำการอัปเดตระบบในฝั่งหุ้นไทย ทีมพัฒนา (AI) จะต้องศึกษาและจดจำปัญหาทางเทคนิคที่เราค้นพบในโครงการนี้:

### 🚨 ปัญหาที่ 1: การบล็อกไฟล์ที่มีขีดล่าง `_` ของ GitHub Pages (404 Error)
*   **สาเหตุ**: เมื่อบอทรันเซฟไฟล์เช่น `_SPX.json` ลงเซิร์ฟเวอร์ GitHub Pages เมื่อเข้าชมผ่านเบราว์เซอร์จะพบข้อผิดพลาด 404 (File Not Found) ทันที เนื่องจากระบบคอมไพเลอร์ Jekyll ของ GitHub Pages จะละเลยไฟล์หรือโฟลเดอร์ใดๆ ที่ขึ้นต้นด้วยเครื่องหมายขีดล่าง (`_`) เป็นค่าเริ่มต้นเพื่อป้องกันความปลอดภัย
*   **วิธีแก้ไข**: สร้างไฟล์เปล่าชื่อ `.nojekyll` ไว้ที่รากโฟลเดอร์หลักของโปรเจกต์ และในโฟลเดอร์ `docs/` เพื่อสั่งให้ GitHub Pages ปิดการแปลงเว็บด้วย Jekyll และเปิดให้บริการไฟล์ทุกไฟล์โดยตรง
*   **การประยุกต์ใช้กับหุ้นไทย**: โค้ดฝั่งไทยสามารถบันทึกประวัติดัชนีด้วยรูปแบบไฟล์ที่มีเครื่องหมายขีดล่างได้ทันที เช่น `_SET.json` เพราะเราได้ฝังไฟล์ `.nojekyll` ลงใน Repository เรียบร้อยแล้ว

### 🚨 ปัญหาที่ 2: กราฟดัชนีหลักโหลดข้อมูลไม่ครบถ้วน (Interval/Period mismatch)
*   **สาเหตุ**: ข้อมูลประวัติดัชนีตลาดหลักของ yfinance (เช่น `^GSPC`) มักไม่มีคีย์บางอย่างเหมือนหุ้นปกติ หรือการดาวน์โหลดไม่กำหนดช่วงเวลาอย่างชัดเจน ทำให้ไฟล์ JSON ประวัติมีข้อมูลสั้นมากและไม่รองรับการซูมช่วงเวลา 1M, 6M, 1Y หรือ All
*   **วิธีแก้ไข**: ปรับปรุงโค้ดประวัติในบอทให้เรียกใช้ `.history(period="5d")` สำหรับค่าล่าสุด และระบบประวัติรวมให้สั่งเซฟข้อมูลระดับย้อนหลัง `5y` โดยคัดกรองเฉพาะวันที่ไม่มีค่าว่าง (Null) และบันทึกราคาปิดอย่างสม่ำเสมอ
*   **การประยุกต์ใช้กับหุ้นไทย**: บอทฝั่งไทยควรดึงราคาดัชนีของไทยด้วยความละเอียดที่ตรงกันและบันทึกราคาย้อนหลังครบ 5 ปี เผื่อไว้สำหรับการสลับช่วงเวลาบนหน้าต่างกราฟของ Dashboard

### 🚨 ปัญหาที่ 3: ระบบเบราว์เซอร์ค้าง Cache หน้าเว็บเก่า (Service Worker Caching)
*   **สาเหตุ**: เมื่อเราทำการแก้ไขโค้ด HTML/CSS ในแผง Dashboard ของหน้าหลัก แต่เมื่อผู้ใช้เปิดใช้งานผ่านมือถือหรือเบราว์เซอร์ปกติกลับไม่พบความเปลี่ยนแปลง หรือหน้าเว็บค้าง เนื่องจากระบบเบราว์เซอร์ทำการเก็บแคชหน้าเว็บไว้อย่างแน่นหนาผ่าน Service Worker (`sw.js`)
*   **วิธีแก้ไข**: ทุกครั้งที่มีการอัปเกรดระบบหรือปรับเปลี่ยนโค้ดหน้าบ้าน จะต้องเข้าไปแก้ไขค่าตัวแปรเวอร์ชันแคชในไฟล์ `docs/sw.js` (เช่น เปลี่ยนเลขจาก `thai-top100-v20260618-4` ไปเป็นเวอร์ชันที่สูงขึ้น) เพื่อบังคับให้เบราว์เซอร์รับรู้ว่ามีเนื้อหาใหม่ ทำการล้างแคชเก่าทิ้ง และโหลด HTML/CSS หน้ากากใหม่จากโฮสต์ทันที
*   **การประยุกต์ใช้กับหุ้นไทย**: เมื่อทำการเปลี่ยน UI ของแอปหุ้นไทยใน `docs/thai/index.html` จะต้องอัปเดต Service Worker ที่เกี่ยวข้องในพาร์ทของแอปไทยด้วยเสมอ
